# Launcher icon and desktop task controls - 0.8.0

## Scope and decisions

The user directly requested all changes below. Their design specifies extending
colors from the existing icon to a square so Android applies its own mask, and
asks us to choose the most natural shared column term. Use "Completed" as the
status heading on both platforms, with "Clear Completed Tasks" for the action.
Keep existing colors, task data, confirmation and startup behavior. No unresolved
product decision is needed for this scope.

<!-- md-block {"id":"B01","dependsOn":[]} -->
## B01 - Android adaptive launcher icon

Generate a fully opaque square foreground from the existing logo, extending its
outer colors beyond the visible artwork so the launcher supplies the shape.
Preserve the three leaves and their existing colors; avoid white borders and
any second rounded outline. Preserve launcher branding for older Android.
Verify resource geometry and inspect the actual Redmi launcher after an in-place
signed install, preserving the existing session and data.

<!-- md-block {"id":"B02","dependsOn":[]} -->
## B02 - Consistent completion terminology and clear action

Use Completed for the task column on Windows and Android; align the clear action
text with that terminology. On Windows reveal the clear button only while the
pointer is over the completed header, with a stable header/count layout. Android
keeps a visible touch-accessible button and the existing confirmation, disabled
state and single-submit protection. Verify both platforms and pointer transitions.

<!-- md-block {"id":"B03","dependsOn":[]} -->
## B03 - Windows task-form keyboard and initial focus

In the description field, Ctrl+Enter invokes the same enabled submission as the
button; plain Enter inserts a newline. Guard invalid, unchanged and pending forms.
Apply this consistently to creating and editing tasks on Windows. Opening an
edit form must not auto-focus or select any field; a click can focus it normally.
Keep Android touch behavior and form validation unchanged. Verify keyboard and
focus behavior, including disabled and in-flight saves.

## Validation and delivery

- Flutter analysis is clean and all 230 tests pass, including keyboard shortcut
  submission/disabled/pending cases, initial focus, hover visibility and stable
  header geometry, and Android touch accessibility. The API build and 14 tests
  also pass after version alignment.
- The Android launcher now uses a full opaque vector foreground reconstructed
  from the original logo's geometry and exact colors, with its outer colors
  extending through the 108dp canvas. The launcher supplies the outer mask.
  The signed 0.8.0+17 APK was verified and installed in place on the Redmi; the
  launcher screenshot shows the device's rounded mask without a white border.
  The user confirmed that its curvature is now as requested.
- A normal Windows release was built at the taskbar path. Real Windows UI
  checks show Completed and the clear button on header hover, no automatic
  edit-field focus and a new line from Enter in a description. The edit was
  cancelled; the fixture's original four tasks and board order remain intact.
  The user then confirmed Ctrl+Enter saves the additional `QA` task in the
  authorized development board. Disabled and in-flight conditions are also
  covered by widget tests.
- Tests and builds ran in parallel; cancelled builds were restarted after a lint
  fix and an old test expectation was updated for the requested focus behavior.
- Open PR: https://github.com/macorisd/microplanner/pull/9 (target main,
