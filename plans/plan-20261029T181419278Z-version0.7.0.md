# Startup, column memory and sync motion - 0.7.0

## Scope

Base: merged 0.6.0. Target app/API: 0.7.0, app build 16. The user replaced
Android's earlier shuffling intro after trying it on the Redmi: keep its logo
static during loading, then zoom into the color of the remembered column.
Keep the current Windows startup shuffle. Reuse that shuffle in sync notices
on both platforms. All current colors, user data and account boundaries remain.
The user explicitly delegated creative execution and requested implementation.

## B01 - Platform-specific startup

Windows retains the already implemented flat three-leaf shuffle. Its shared
motion timeline survives bootstrap/session/workspace changes, repaints only the
logo and stops when no loader uses it. No palette or trajectory changes.

Android shows only the original static icon at the full-window center, matching
its native launch frame. Remove the native animated-vector experiment. Once the
workspace, last board and column preference are ready, lay out the destination
before starting one 600ms zoom into the corresponding logo leaf: Completed is
green, Late yellow, Upcoming blue. The chosen color grows to cover the window
and reveals the matching column. No blur, perspective, offscreen saveLayer or
rebuilding of the task tree on every animation tick. The loading cover blocks
underlying input and semantics until the transition completes.

On both platforms, finish the initial cloud synchronization behind the logo,
even when a cached workspace is available. Only then reveal the ready board;
do not show an initial busy notification over it. If that attempt fails, expose
the offline cached workspace or existing retry screen. Later refreshes retain
their floating status notice and never return to the startup screen merely
because synchronization is in progress.

Do not replay this zoom on refresh, navigation or board changes. Reduced motion
skips the zoom and uses a static logo. Login, cancellation, errors, retry and
offline cached access retain their existing behavior. Bootstrap must draw its
first loading frame before platform storage initialization; no minimum waiting
period is added. Android's native-to-Flutter handoff has no overlapping fade.

Acceptance: matching static frame/center; each remembered column selects its
own color and destination; the already built dashboard survives the transition;
no replay on normal rebuilds; no ticker after completion; narrow/landscape and
reduced-motion cases remain usable. Windows keeps its existing shuffle.

## B02 - Remember each board's Android column

Keep the existing account/device-local last-board preference. Additionally keep
a per-account/device map from stable board ID to column index (0/1/2). Read it
once during session restoration so board changes need no storage round trip.
Never put this preference in MongoDB or trigger a workspace write for navigation.
Upcoming remains the fallback for a board with no history or unavailable storage.

Record manual destinations immediately when chosen, and the visible column
during a drag, before a background pause can cancel the snap animation.
Restore each board's latest column when reopening the app and when revisiting
that board. Refresh preserves the visible column. Serialize writes per account,
reject stale account reads, bound failed storage reads and keep data accessible
if preferences fail. Old-account writes must never enter the new account.

<!-- md-question {"id":"Q01","block":"B02","status":"answered","decision":"Restore each board's remembered column when switching boards as well as at app startup."} -->
### Q01 - Column behavior on board changes

- A. Restore the board's last column on every visit (recommended: each board
  retains where the user left it).
- B. Restore only on startup; board switches still open Upcoming.

User answer: A. Restore when switching boards too. Scope remains per account
and device, matching the existing last-board decision. Without history use
Upcoming. This explicitly replaces the earlier Upcoming-on-board-switch rule.

Acceptance: independent boards/accounts/devices; restart and board return restore
selection; rapid changes and sign-out preserve the final values; refresh and
offline navigation do not reset it; invalid/missing storage falls back safely.

## B03 - Reuse the Windows shuffle in sync notices

Replace the cloud notice's circular spinner with the same flat three-leaf logo

shift workspace geometry, restart the entire workspace or leave a hidden ticker.
