# microplanner 0.3.0 - Floating status cards and a fluid interface

## Outcome and scope

Make the existing Windows and Android interfaces feel responsive, expressive and
coherent. Replace the loading strip that pushes the dashboard down with a rounded
notification card layered over the interface. Apply a shared motion language to
the complete existing interaction surface: sign-in, startup, boards, subjects,
task lists, task actions, forms, dialogs and cloud feedback.

Baseline: `v0.2.7`, commit `8dbfb6715caed2482db89c8bf42b3f6fd0bef512`.
Target: minor `0.3.0`, with the next available Android build number (currently 10).
Implementation branch: `feature/animated-interface`.

The user explicitly requested both platforms, a notification-like loading card
with rounded corners, and enjoyable, fluid animation throughout the app. Existing
mint colors, compact card spacing, Google avatar, Android system bar integration,
and platform-specific controls are the visual baseline.

## Proposed design direction

- Expressive, short transitions with gentle easing, small positional movement and
  restrained spring-like settling on appropriate controls.
- Starting timing scale: about 120 ms for press/hover feedback, 220 ms for normal
  state changes and 320 ms for larger entrances. Tune on the real devices.
- Small movement distances (roughly 8-16 logical pixels) and bounded staggered
  entrances. Controls remain responsive while a transition is running.
- Animations explain a change: where a task went, which board is selected, whether
  a dialog opened, or whether the cloud is loading or saving.
- Respect the system request to reduce/remove animations. This is automatic and
  does not add a new settings flow.

No unresolved functional or account/service setup decisions remain. The user
approved the visual direction and complete implementation through the interactive
question; the approval evidence is recorded in the plan metadata.

## B01 - Shared motion foundation

Create reusable timing, curves and transition primitives compatible with the
installed Flutter SDK. Use Flutter animation widgets and controllers where each
fits the interaction. Keep the existing SDK and prefer SDK components over adding
an animation dependency.

Acceptance criteria:

- Shared motion tokens keep durations and easing consistent across the app.
- Interrupted and rapidly repeated interactions settle into the latest state.
- Honor reduced motion for both custom implicit and explicit animations.
- Dispose controllers/timers and stop offscreen animation work.
- Press feedback is immediate; animation does not delay or duplicate an action.

## B02 - Floating cloud status notification

Replace the layout-affecting loading/offline/error strip in AccountDashboard with
a responsive top overlay. The card uses the existing palette, rounded corners,
gentle elevation, a meaningful icon/progress indicator and concise English text.
It animates into place and fades/slides away when its state resolves.

Behavior and limits:

- Show loading/refreshing and saving activity in the same visual language.
- Give offline/error states clear text and a reachable Retry action; keep them
  available until resolved rather than hiding actionable failures on a timer.
- Present one coordinated status card instead of stacking duplicate notices.
- Keep the existing cached dashboard visible while refreshing. When there is no
  cached workspace, retain a clear initial loading/empty-state surface.
- Existing local-data import consent remains a separate explicit action.

Acceptance criteria:

- Showing, changing and removing a notification does not change dashboard,
  column, task or scroll positions.
- The card fits narrow Android and desktop layouts, safe areas and enlarged text.
- Absent notices intercept no input; Retry is disabled during an active request.
- No loading/retry flicker, misleading saved status, or loss of error information.
- Offline data remains read-only and import still requires account confirmation.

## B03 - Navigation, sidebar and subjects

Animate board changes, selected board styling, board/subject view changes,
inline renaming, sidebar actions and profile image loading. Coordinate motion
with the existing Android drawer/page gestures and desktop sidebar resize.

Acceptance criteria:

- Board content and headings transition together without losing selection.
- Subjects and back navigation use a consistent transition direction.
- Hover actions fade on Windows and remain persistently visible on Android.
- Touch scrolling and long-press board reordering remain distinct.
- Sidebar width changes, drawer gestures and resize handles remain responsive.
- Profile images can fade in without ever showing another account's avatar.

<!-- md-block {"id":"B04","dependsOn":["B01","B03"]} -->
## B04 - Task cards, lists and completion feedback

Animate list insertions, removals and state changes using stable task identity.
Give completion controls, column counts, card interactions and empty states
coordinated feedback. Use brief, bounded list entrances on board changes and
initial display instead of restarting every visible card on an ordinary rebuild.

Acceptance criteria:

- Add, edit, complete, uncomplete and delete actions update the correct task.
- Confirmed completion/removal moves or removes a task cleanly and updates counts.
- Pending/failed cloud writes do not masquerade as successful saved changes.
- No duplicated cards, stale outgoing tasks, lost scroll positions or repeated
  mutations when users click rapidly or change boards during a transition.
- Retain 48dp touch hit regions, checkbox/date alignment, compact visual rows,
  text-sized subject badges and readable long titles/subjects.
- Existing Android column snapping and desktop hover behavior remain intact.

<!-- md-block {"id":"B05","dependsOn":["B01","B02"]} -->
## B05 - Forms, dialogs, authentication and control feedback

Apply coherent opening/closing and state transitions to task, board, subject,
import and deletion dialogs; sign-in/startup states; buttons and FAB; field focus;
priority/color selectors; dropdowns; and existing date/time pickers. Retain useful
platform-native motion where it already fits rather than adding duplicate effects.

Acceptance criteria:

- Dialog surfaces and modal backdrops open/close smoothly and support keyboard,
  Escape/back, cancel and repeated open/close actions.
- Editing on Android still opens without automatically focusing the task name.
- Keyboard insets and validation/save errors animate without overflow or loss of
  typed values, selected subjects, deadlines, focus or scroll position.
- Login/loading states transition cleanly; account changes immediately discard
  outgoing account content and dialogs, including any animation caches.
- Buttons and selectors respond to press, hover, focus, disabled and busy states
  consistently without adding continuous decorative motion to idle screens.
