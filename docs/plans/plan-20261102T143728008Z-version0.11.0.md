# PLAN - version 0.11.0 (minor)

## Objective

Refresh navigation and board configuration, introduce profile and settings pages, and support editable task type lists without losing existing user data. Scope and acceptance criteria below reflect the request; additional ideas remain subject to user decisions.

<!-- md-block {"id":"B01","dependsOn":[]} -->
## B01 - Sidebar and Weekly Plan

Add a clickable Weekly Plan navigation item before Boards, opening a central Coming Soon page. Boards is an expanded-by-default collapsible heading. Board rows show their icon and title, with edit and delete actions on hover; selecting a row opens the board. Preserve board reordering and make all actions usable on touch and with a keyboard. Move sign out from the sidebar to Profile. Existing navigation and board selection continue to work.

Provide touch-accessible board actions without relying on hover, visible keyboard focus and accessible labels. Preserve the existing last-board and delete confirmation safeguards. Weekly Plan, Profile and Settings must provide a clear route back to a board on Windows and Android.

<!-- md-block {"id":"B02","dependsOn":[]} -->
## B02 - Board editor, subjects and task types

Provide a board editor consistent with the task editor, including name, icon from a broad shared icon selection, and color. Show board icon and name in its color and use a very pastel version behind the board columns. Provide convenient equivalent editable and reorderable subject and task type lists: subjects have a color and start empty on new boards; types have an icon and initially use the existing default types. Allow up to 25 of each per board, showing the limit only when another is attempted. Validate names, limits and edge cases. Confirm destructive changes and report the number of existing tasks that will lose their subject or type. Existing tasks and boards must be migrated safely and retain their associations unless explicitly removed. Coordinate validation, persistence and synchronization across clients and API.

Use two clearly labeled editable, reorderable lists in the editor, with inline summaries and dedicated controls for adding and editing entries. Offer the same navigable icon collection for boards and types. User clarification: boards and subjects share the existing vivid pastel subject palette, while board backgrounds use a much paler version. The editor supports save and cancel; cancellation leaves saved data unchanged. A destructive confirmation states how many tasks lose each removed association. Failed or conflicting saves must not silently discard data.

Use a 50-character limit for newly created or renamed subject and type names, with nonempty trimmed names; preserve longer existing names without truncation or blocking unrelated changes. Preserve existing boards with more than 25 subjects without deleting data; prevent adding more until below the limit. Existing board/task type assignments migrate to the corresponding board-specific types, preserving the unassigned state. Newly created boards start with the current six named types: Homework, Test, Presentation, Project, Reading and Other; No type remains an unassigned choice, not a removable type. Subject and type reordering must not change task associations. Prevent stale clients or concurrent edits from silently removing new data.

## B03 - Default task type lists

Settings contains Customization, with a paintbrush icon, then Boards and Default lists of task types. Offer five initial lists including Academic tasks and Software development. Users can create, edit and delete lists and select a list in a board editor to set that board's task types. Replacing a list must confirm any affected task assignments as described in B02. Preserve per-account data and synchronize across devices.

Initial proposals: Academic tasks (Homework, Test, Presentation, Project, Reading, Other); Software development (Feature, Bug, Refactor, Testing, Documentation, Review); Work (Meeting, Report, Research, Planning, Follow-up, Other); Personal life (Errand, Appointment, Household, Health, Finance, Other); Creative projects (Idea, Research, Draft, Design, Review, Finalize). Give each type a suitable icon from the shared collection. Editable lists have a nonempty validated name and at most 25 types; preserve task assignments according to Q04 when applying a list. Allow an empty type list and keep the unassigned task choice available. Confirm deleting a default list; deleting or editing a template does not modify boards that previously copied it.

<!-- md-question {"id":"Q03","block":"B03","status":"answered","decision":"Independent copy"} -->
### Q03 - Relationship between default lists and boards

- A. Independent copy (**recommended**): applying a default copies its types to the board; later changes to either do not change the other.
- B. Linked list: later changes to a default automatically update boards using it, including possible effects on assigned tasks.
- C. Choose a different behavior.

User response: independent copy; board and template are edited separately. Consequences: applying copies types to a board; later edits to either do not propagate to the other.
